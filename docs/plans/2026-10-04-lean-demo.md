# Lean demo implementation plan

**Goal:** Ship a working three-screen demo container and measure it against a 200 MB RAM target.

**Architecture:** Python/FastAPI with fixed Pillow raster layouts, one scheduled refresh, SQLite metadata and persistent PNG cache. Image requests read the cache only. Critical alerts remain deterministic and separate from the three ordinary-item limit.

**Tech stack:** Python 3.12, FastAPI, Uvicorn, Pydantic settings, Pillow, APScheduler, stdlib SQLite.

## Accepted direction
The existing project brief supplies the design; the implementation request authorizes starting. Astra reviewed architecture; Luna agents implement bounded contracts/rules and renderer tasks. Integrator owns deployment, platform integration, checks and documentation. No Git repository exists, so no worktrees or commits are created.

1. T0: record unknown hardware/provider details, use 800×600 and Europe/Lisbon defaults; supersede Chromium with Pillow for the memory goal.
2. T1/T5: write failing validation/rule tests, implement contracts and deterministic selection, align JSON schemas and synthetic fixtures. Reject naive times, unknown IDs, invalid severity/layout; preserve every protected ID independently of ordinary selection.
3. T3: write failing render tests, implement three grayscale layouts with date/time and DEMO label, bounded text and rotation. Inspect actual PNGs.
4. T2/T9: write failing lifecycle/cache/HTTP tests, implement validated settings, serial refresh, durable cache and status, non-root container. Keep last good image and timestamp after failure/restart.
5. Integration: run full tests, lint, formatting, types; build container. Measure cgroup peak under startup, repeated refresh, failure recovery and concurrent cached reads with 190 MiB cap and no swap. Record architecture and limitations.
6. Astra reviews scope, correctness and bloat; fix material findings and rerun affected checks.

## Scope boundary
This delivers the demo foundation, not all V1 acceptance. Live ICS/weather/RSS, optional AI, physical Kindle controls and N100 validation remain explicit follow-up tasks. No invented providers, family details or source URLs.
